# なんちゃってECサイト 構想メモ

## ■ 目的

前回のタスク管理アプリに続く次の学習・ポートフォリオ用アプリとして、
「なんちゃってECサイト」を開発する。

実際の決済や配送などは行わず、
ECサイトらしい設計・状態管理・ドメインモデリングを学ぶことを目的とする。

---

# ■ 開発方針

## ■ 基本方針

- 「実務寄りの設計」を意識する
- ただし機能過多にはしない
- 小さく作って段階的に拡張する
- 学習テーマを明確化する

---

# ■ 技術スタック（予定）

## Frontend

- Next.js
- TypeScript

### 補足

- App Router を採用予定
- Next.js は画面/UI/ルーティング用途を主目的とする
- API Routes への依存は最小限
- Server Actions 等の高度機能は必要になってから検討

---

## Backend

- Go
- Gin

### 補足

- REST API 構成
- フロント・バック分離構成を維持
- 業務ロジックはGo側に集約する

---

## Database

- PostgreSQL

---

## Infrastructure

- Docker / Docker Compose

---

# ■ アーキテクチャ方針

## ■ フロント・バック分離構成

```txt
Next.js (Frontend)
        ↓
Go API Server
        ↓
PostgreSQL
```

### 方針

- Next.js 側に業務ロジックを寄せすぎない
- Go API を主体とした構成を維持する
- 「Goバックエンド + Next.jsフロント」の実務寄り構成を目指す

---

# ■ Next.js 採用方針

## ■ 採用理由

- 次のステップとして新しい技術に挑戦したい
- ECサイトとルーティング構成の相性が良い
- ポートフォリオとして見栄えが強い
- React/Vite は既に経験済み

---

## ■ リスク認識

以下が重くなる可能性あり。

- Server / Client Component
- 認証設計
- SSR / SSG 周辺理解
- キャッシュ戦略
- Go API との責務分離

---

## ■ 対応方針

まずは小規模に検証する。

### Phase0（技術検証）

- 商品一覧
- 商品詳細
- Go API 疎通
- 簡単な認証状態保持

を試作し、
重すぎる場合は React + Vite へ戻す判断も許容する。

---

# ■ CMS 方針

## ■ 初期フェーズでは採用しない

### 理由

今回学びたい対象が以下のため。

- 商品管理
- 在庫
- カート
- 注文
- 管理画面
- DB設計
- API設計

これらを自作した方が学習効果が高い。

---

## ■ 将来的なCMS利用候補

必要になった場合のみ検討。

### 対象例

- 商品紹介文
- 特集ページ
- お知らせ
- ブログ

### 想定

- headless CMS の後付け導入
- コンテンツ領域のみCMS化

---

# ■ DDD 方針

## ■ 軽量DDDを試験導入する

### 目的

- ドメインモデリング経験を積む
- ECドメインを整理して扱う
- 業務ロジックの責務分離を学ぶ

---

## ■ 導入予定要素

- Entity
- Value Object
- Domain Service
- Repository パターン（必要になれば）
- Aggregate の概念

---

## ■ 現時点でやらないもの

- CQRS
- Event Sourcing
- Domain Event 全面導入
- 過剰抽象化

---

# ■ TDD 方針

## ■ 部分導入を行う

### 対象

ビジネスロジックが強い箇所を優先。

例：

- カート追加
- 在庫チェック
- 注文確定
- 金額計算
- ステータス変更
- キャンセル条件判定

---

## ■ 無理にTDDしない箇所

- 単純CRUD
- UI実装
- 一覧取得系

---

# ■ 初期実装スコープ
