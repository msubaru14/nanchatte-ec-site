# 認証画面

## 目的

一般ユーザーが画面上からログインまたはユーザー登録を行い、認証済み状態で後続の操作へ進めるようにする。

共通 Header には認証状態に応じた導線を表示し、ログイン済みユーザーが画面上からログアウトできるようにする。

Phase1では、Browser から Go API を直接呼び出さず、Next.js Route Handler の認証BFFを利用する。

---

## 対象画面

| 画面 | パス | 目的 |
| --- | --- | --- |
| ログイン | `/login` | 既存ユーザーがログインする |
| ユーザー登録 | `/register` | 新規ユーザーを登録し、そのままログイン状態にする |

---

## 利用API

```txt
POST /api/auth/login
POST /api/auth/register
POST /api/auth/logout
GET  /api/auth/me
```

- login / register 成功時の token は BFF が httpOnly cookie として保存する
- logout 実行時は BFF が Go API の成功/失敗に関わらず認証 cookie を削除する
- frontend は token を Browser JavaScript で保持しない
- 画面初期表示後の認証状態は `GET /api/auth/me` の結果から復元する

---

## ログイン画面

### 入力項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| メールアドレス | 必須 | ログインID |
| パスワード | 必須 | 入力値は画面上に平文表示しない |

### 動作

- 送信時に認証BFFの login API を呼び出す
- 成功時は返却された user を frontend の認証状態へ反映する
- ユーザー登録画面への導線を表示する

---

## ユーザー登録画面

### 入力項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 表示名 | 必須 | User の `name` |
| メールアドレス | 必須 | ログインID |
| パスワード | 必須 | 登録APIのvalidationに従う |

### 動作

- 送信時に認証BFFの register API を呼び出す
- 成功時は返却された user を frontend の認証状態へ反映する
- ログイン画面への導線を表示する

---

## 認証状態反映

- login / register 成功時は `AuthContext` へ user を反映する
- 初期表示時は `GET /api/auth/me` によりログイン済み状態を復元する
- 認証状態の判断に access token / refresh token の Browser JavaScript 読み取りは使用しない

---

## Header の認証導線

### 未ログイン時

- `ログイン` 導線を表示する
- `ユーザー登録` 導線を表示する
- `カート` 導線とCart件数は表示しない
- Cart取得は行わない

### ログイン済み時

- `/cart` への `カート` 導線を表示する
- ログイン中ユーザーの表示名を `/me` への導線として表示する
- `ログアウト` 導線を表示する
- Cart BFFを経由してCartを取得し、`cart_items` の `quantity` 合計が1以上の場合のみ件数を表示する
- 空Cartの場合は `カート` 導線だけを表示し、件数は表示しない
- Cart取得中は読み込み中表示を出す
- Cart取得失敗時は `カート` 導線を残して件数なし表示へフォールバックする
- Cart取得が `UNAUTHORIZED` の場合は未ログイン状態として扱う
- 注文履歴や自分のレビュー一覧などのユーザー向け導線は、Headerに個別表示せずマイページへ集約する

### Cart件数の更新

- Headerの初回表示時に、ログイン済みであればCart件数を取得する
- login後は認証状態更新に伴ってCart件数を取得する
- logout後はCart件数と `カート` 導線を表示しない
- Cart追加、数量変更、商品削除、全削除の成功後はCartを再取得して件数を更新する
- Phase1では複数タブ間や他デバイス操作によるリアルタイム同期は扱わない

### ログアウト動作

- Header の logout 操作時に認証BFFの `POST /api/auth/logout` を呼び出す
- logout 後は `AuthContext` の user を `null` に更新する
- logout 後は `/products` へ遷移する
- backend 側の revoke に失敗した場合も、BFF が cookie を削除した後は未ログイン状態へ遷移する
- logout 失敗時は API の `error.message` を Header に表示する

---

## 成功時遷移

- query parameter に `returnTo` が指定されている場合、内部パスのみ遷移先として許可する
- 外部URL、protocol-relative URL、解析できない値は遷移先に使用しない
- 許可できる `returnTo` がない場合は `/products` へ遷移する

例:

| `returnTo` | 遷移先 |
| --- | --- |
| `/products/1` | `/products/1` |
| `/products?category=keyboard` | `/products?category=keyboard` |
| `https://example.com` | `/products` |
| `//example.com` | `/products` |

---

## エラー表示

- APIから返った `error.message` をフォーム上部に表示する
- validation details の対象項目が判別できる場合、該当する入力欄付近にも表示する
- 表示文言や配置の詳細な調整は後続のUI改善で扱えるものとする

---

## デザイン方針

- 白ベースのフォームカード
- 既存のネイビーheaderと青アクセントに合わせる
- desktop / tablet / mobile で横スクロールを発生させない

---

## 対象外

- Cart追加時のログイン誘導
- 認証必須ページのガード
- admin向け Header 分岐 / 認証制御
- Header の dropdown menu 高度化
- avatar表示
- toast通知最適化
- password再設定
- OAuth
- MFA
