# 設計ドキュメント索引

このドキュメントは、基本設計資料を参照するときの入口として使う。

実装・調査・レビュー時に「どの設計項目はどの資料を読むか」を迷わないようにするための索引。

---

## まず読む資料

### 1. 全体像を掴む

- `docs/構想メモ.md`
  - 目的
  - 技術スタック
  - アーキテクチャ方針
  - Phase1のスコープ
  - 今回の学習テーマ

### 2. 基本設計の概略を掴む

- `docs/基本設計_初期案.md`
  - 主要ドメイン
  - 初期DBテーブル案
  - API設計初期案
  - 画面設計初期案
  - 軽量DDDの切り方
  - TDD対象
  - Phase1実装順案

### 3. 現在の詳細設計を見る

- `docs/api/API.md`
  - API一覧
  - 権限分類
  - APIごとの役割
- `docs/api/openapi.yaml`
  - 実装済みAPIの request / response / error 詳細仕様
- `docs/ui/画面一覧.md`
  - Phase1で作る画面
  - 一般ユーザー画面
  - 管理者画面
- `docs/ui/認証画面.md`
  - ログイン画面
  - ユーザー登録画面
  - Header の認証状態反映 / logout 導線 / Cart件数表示
  - 成功時遷移 / エラー表示
- `docs/ui/商品一覧画面.md`
  - 商品一覧画面の表示内容
  - 商品カード
  - loading / error
  - レスポンシブ方針
- `docs/ui/商品詳細画面.md`
  - 商品詳細画面の表示内容
  - 数量指定 / Cart追加導線
  - Cart追加成功後のHeader件数更新
  - 在庫不足時の数量調整提案
  - 未ログイン時の認証導線
- `docs/database/ER.md`
  - Mermaid形式のER図
- `docs/database/DB制約整理.md`
  - テーブル制約
  - unique / check / index 候補
  - DBで守るルールとアプリケーションで守るルールの切り分け
- `docs/database/dbdiagram.dbml`
  - dbdiagram.io用DBML
  - DDL / migration作成前のDB構造確認用

## 実装時の読み方

### DB / migrationを触るとき

1. `docs/database/DB制約整理.md`
2. `docs/database/dbdiagram.dbml`
3. `docs/database/ER.md`
4. 対象ドメインの `docs/domains/*_ドメイン_振る舞い整理.md`

### APIを実装するとき

1. `docs/api/API.md`
2. `docs/api/openapi.yaml`
3. `docs/domains/Userドメイン_振る舞い整理.md`
4. 対象ドメインの `docs/domains/*_ドメイン_振る舞い整理.md`
5. `docs/database/DB制約整理.md`

### 画面を実装するとき

1. `docs/ui/画面一覧.md`
2. `docs/api/API.md`
3. 対象ドメインの `docs/domains/*_ドメイン_振る舞い整理.md`

### 業務ルールを実装・テストするとき

1. 対象ドメインの `docs/domains/*_ドメイン_振る舞い整理.md`
2. `docs/基本設計_初期案.md` のTDD対象
3. `docs/database/DB制約整理.md` の「DBだけでは守らない業務ルール」

## 注意

- `docs/基本設計_初期案.md` は初期案なので、詳細は後から作成した資料を優先する
- DB構造は `docs/database/DB制約整理.md` と `docs/database/dbdiagram.dbml` を優先する
- APIの一覧・役割は `docs/api/API.md`、実装済みの入出力・エラー契約は `docs/api/openapi.yaml` を優先する
- 画面は `docs/ui/画面一覧.md` を優先する
- ドメインの振る舞いは各 `docs/domains/*_ドメイン_振る舞い整理.md` を優先する
